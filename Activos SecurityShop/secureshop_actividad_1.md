## 1. Identificación, Clasificación, Amenazas y Controles de Activos

| Activo | Tipo | Consecuencia si es accedido, modificado o queda indisponible | Amenazas Identificadas  | Controles de Seguridad Recomendados |
| :--- | :--- | :--- | :--- | :--- |
| **1. Datos personales de usuarios** | Información / Datos | **Acceso no autorizado:** Filtración de información privada del cliente y daño a la imagen de la empresa.<br>**Modificación:** Direcciones o contactos cambiados, causando envíos a lugares equivocados o robo de cuenta.<br>**Indisponibilidad:** No se pueden consultar los datos del cliente para procesar las compras. | 1. Engaños o hackeo a la base de datos para ver la lista de clientes.<br>2. Espionaje de datos cuando el cliente navega en la página.<br>3. Robo masivo de información por descuido de una contraseña. | 1. Filtrar y revisar todo lo que el usuario escribe en la página.<br>2. Usar conexiones seguras de internet (candado verde en la página/HTTPS).<br>3. Guardar la información encriptada (como un código secreto) y limitar quién puede verla. |
| **2. Credenciales y tokens de autenticación** | Información / Datos | **Acceso no autorizado:** Entrada de desconocidos a cuentas de clientes o administradores.<br>**Modificación:** Cambio no deseado de contraseñas, dejando a los usuarios sin acceso.<br>**Indisponibilidad:** Nadie puede iniciar sesión en la tienda web. | 1. Intentos repetidos con listas de claves hasta adivinar la contraseña.<br>2. Robo de la clave digital de sesión mediante enlaces o virus engañosos.<br>3. Guardar accidentalmente contraseñas en archivos públicos de trabajo. | 1. Pedir un código adicional al celular (verificación en dos pasos) y bloquear tras varios intentos fallidos.<br>2. Usar pases digitales de entrada que duren poco tiempo.<br>3. Usar herramientas que escaneen los archivos del proyecto buscando claves por error. |
| **3. Catálogo e inventario de productos** | Información / Datos | **Acceso no autorizado:** Competidores ven listas de precios y productos guardados.<br>**Modificación:** Cambio de precios a valores absurdos, provocando pérdidas de dinero.<br>**Indisponibilidad:** Los clientes no pueden ver ni buscar qué comprar. | 1. Trampas en la página web para alterar el precio de un producto.<br>2. Programas automáticos de la competencia copiando todo el catálogo constantemente.<br>3. Borrado malintencionado del inventario de productos. | 1. Asegurar que solo el administrador pueda cambiar precios desde el panel privado.<br>2. Bloquear accesos repetitivos y sospechosos que intenten copiar la página.<br>3. Tener respaldos diarios de la información para recuperarla si se borra. |
| **4. Historial de pedidos y transacciones** | Información / Datos | **Acceso no autorizado:** Curiosos ven las compras pasadas de otras personas.<br>**Modificación:** Cambiar el estado de una compra para simular que ya se pagó sin haber hecho el depósito.<br>**Indisponibilidad:** No se pueden revisar los pedidos realizados ni saber qué enviar. | 1. Cambiar los números de la página web para ver las compras de otros usuarios.<br>2. Alterar el registro para marcar un pedido como pagado manualmente.<br>3. Fallas en el sistema mientras muchas personas compran al mismo tiempo. | 1. Comprobar siempre que la persona solo pueda ver sus propias compras.<br>2. Validar automáticamente los pagos directamente con el banco.<br>3. Contar con servidores de respaldo que mantengan las bases de datos siempre funcionando. |
| **5. Código fuente de la aplicación** | Software | **Acceso no autorizado:** Extraños leen cómo funciona el sistema para buscarle fallas.<br>**Modificación:** Inserción de trucos o virus dentro del sistema de la tienda.<br>**Indisponibilidad:** Se detiene el desarrollo y las mejoras en la página web. | 1. Dejar el repositorio de código público por descuido.<br>2. Un desarrollador sube cambios con fallas o código malicioso sin supervisión.<br>3. Pérdida o borrado accidental de todo el proyecto de programación. | 1. Exigir contraseña fuerte e identificación en dos pasos a todo el equipo de desarrollo.<br>2. Obligar a que otra persona revise el código antes de publicar cualquier cambio.<br>3. Mantener copias de seguridad del proyecto en varias ubicaciones seguras. |
| **6. API Gateway** | Servicio / Software | **Acceso no autorizado:** Entrada directa a las zonas privadas del sistema sin pasar por revisión.<br>**Modificación:** Desviar a los clientes a páginas falsas o dañinas.<br>**Indisponibilidad:** La entrada principal colapsa y la tienda web deja de funcionar por completo. | 1. Enviar miles de visitas falsas al mismo tiempo para tumbar la página web.<br>2. Burlar la puerta principal para entrar directo a los servicios internos.<br>3. Aprovechar fallas no corregidas en la puerta de entrada del sistema. | 1. Poner un límite de visitas por minuto por usuario para evitar saturaciones.<br>2. Verificar los permisos del usuario justo en la puerta de entrada.<br>3. Mantener el sistema siempre actualizado con los últimos parches de seguridad. |
| **7. User Service** | Servicio | **Acceso no autorizado:** Manejar la lista de usuarios sin ser administrador.<br>**Modificación:** Alteración de las reglas para crear usuarios falsos.<br>**Indisponibilidad:** Nadie puede registrarse ni consultar sus datos de perfil. | 1. Un usuario común logra engañar al sistema para volverse administrador.<br>2. Enviar peticiones masivas para agotar la memoria del servidor de usuarios.<br>3. Dejar el servicio de usuarios expuesto directamente a internet sin protección. | 1. Asignar roles claros (cliente, vendedor, administrador) y controlar qué puede hacer cada uno.<br>2. Poner límites a la memoria y procesador que puede usar este módulo.<br>3. Esconder este servicio para que solo responda a través de la puerta principal. |
| **8. Product Service** | Servicio | **Acceso no autorizado:** Obtención de información interna del módulo de productos sin estar registrado.<br>**Modificación:** Alterar las cantidades disponibles o información del producto.<br>**Indisponibilidad:** Los clientes no pueden ver la información ni añadir productos al carrito. | 1. Guardar texto engañoso en la descripción del producto para infectar a los compradores.<br>2. Dos personas compran el mismo último producto al mismo tiempo y se vende doble.<br>3. Lentitud extrema por miles de personas consultando el catálogo al mismo tiempo. | 1. Limpiar todo texto escrito por usuarios o administradores para evitar código dañino.<br>2. Controlar las compras una por una para evitar que se venda stock inexistente.<br>3. Usar un sistema de memoria rápida para responder las búsquedas frecuentes sin saturarse. |
| **9. Order Service** | Servicio | **Acceso no autorizado:** Ver detalles de los cobros y llamadas a la pasarela de pagos.<br>**Modificación:** Modificar los montos a pagar antes de procesar la compra.<br>**Indisponibilidad:** No se pueden procesar ni completar los pagos de los clientes. | 1. Cambiar el precio de la compra en la pantalla antes de presionar "pagar".<br>2. Enviar dos veces la misma solicitud para cobrar doble o duplicar un pedido.<br>3. Que la conexión con el banco se corte y la compra quede congelada. | 1. Recalcular y verificar los precios siempre en el servidor principal, jamás en la pantalla del usuario.<br>2. Asignar un número único a cada intento de compra para no procesarlo dos veces.<br>3. Configurar alertas y reintentos automáticos seguros si falla la comunicación bancaria. |
| **10. Bases de Datos de los Microservicios** | Infraestructura / Datos | **Acceso no autorizado:** Copia o robo masivo de la base de datos completa de la empresa.<br>**Modificación:** Borrado o alteración directa de las tablas de información.<br>**Indisponibilidad:** Toda la información desaparece o se bloquea, deteniendo la empresa. | 1. Dejar la base de datos visible para cualquiera en internet sin pedir clave.<br>2. Enviar comandos maliciosos desde la página web para borrar la base de datos.<br>3. Virus tipo secuestro (Ransomware) que encripta la base de datos y pide dinero para liberarla. | 1. Ocultar las bases de datos en redes internas donde nadie desde afuera pueda verlas.<br>2. Crear usuarios de base de datos con permisos estrictos (solo para lo que necesiten).<br>3. Cambiar claves por defecto e implementar encriptación de discos duros. |
| **11. Claves secretas y certificados TLS/SSL** | Información / Datos | **Acceso no autorizado:** Espiar lo que los usuarios escriben en la página aun cuando tenga candado de seguridad.<br>**Modificación:** Cambiar los certificados por unos falsos, mostrando advertencias de sitio no seguro.<br>**Indisponibilidad:** La página muestra alertas de peligro y los usuarios no pueden entrar de forma segura. | 1. Dejar guardadas las claves secretas en lugares donde cualquiera las pueda leer.<br>2. Olvidar renovar el certificado de seguridad cuando se vence.<br>3. Un atacante se coloca en medio de la conexión para interceptar el tráfico. | 1. Guardar todas las llaves en una caja fuerte digital con acceso muy restringido.<br>2. Activar la renovación automática de los certificados de seguridad.<br>3. Obligar al navegador a conectarse únicamente por medio de conexiones seguras. |
| **12. Servidores de Hosting / Clúster de Contenedores** | Infraestructura | **Acceso no autorizado:** Un atacante toma el control del servidor donde funciona la tienda.<br>**Modificación:** Cambiar la configuración de los servidores para instalar programas maliciosos.<br>**Indisponibilidad:** Apagado o caída de todos los servidores de la empresa. | 1. Lograr salir de una aplicación para tomar control del servidor principal.<br>2. Ataques masivos de tráfico para tumbar la capacidad del hosting.<br>3. Dejar accesos de administración abiertos a cualquier persona en internet. | 1. Configurar los programas para que no tengan permisos de administrador del servidor.<br>2. Usar sistemas que aumenten servidores automáticamente si hay muchas visitas.<br>3. Cerrar todas las puertas digitales que no se usen y exigir claves especiales de acceso. |
| **13. Logs y registros de auditoría del sistema** | Datos / Información | **Acceso no autorizado:** Extraños leen los registros de la tienda para ver qué hacen los usuarios.<br>**Modificación:** Borrar los registros de lo sucedido para tapar un robo o hackeo.<br>**Indisponibilidad:** No se pueden revisar los archivos para investigar una falla o ataque. | 1. Escribir datos engañosos en los formularios para confundir los registros del sistema.<br>2. Un atacante borra la lista de historial para que no descubran lo que hizo.<br>3. Guardar contraseñas o tarjetas de crédito por error dentro de los registros del sistema. | 1. Limpiar la información antes de guardarla en el historial del sistema.<br>2. Enviar los registros a un servidor externo donde solo se pueda agregar información, pero jamás borrar.<br>3. Ocultar o tapar automáticamente información confidencial (como poner asteriscos en claves o tarjetas). |
| **14. Servidor CI/CD (Pipeline de despliegue)** | Servicio / Infraestructura | **Acceso no autorizado:** Robar las claves de publicación para subir cambios no autorizados a la página web.<br>**Modificación:** Meter código malicioso en el proceso de actualización sin que el equipo se dé cuenta.<br>**Indisponibilidad:** Se bloquea el sistema que publica las actualizaciones y mejoras de la página. | 1. Que un componente o librería externa descargada contenga un virus oculto.<br>2. Robo de las claves automáticas que se usan para actualizar la página en vivo.<br>3. Modificación no autorizada de los archivos que le dicen al sistema cómo actualizarse. | 1. Escanear automáticamente todas las piezas que se descargan para verificar que no tengan virus.<br>2. Usar claves temporales que expiren rápido en lugar de claves fijas.<br>3. Exigir aprobación de al menos dos personas antes de aplicar cambios al sistema de publicación. |
| **15. Integraciones y API Keys de Pasarelas de Pago**   | Información / Servicio     | **Acceso no autorizado:** Una persona puede utilizar las cuentas o servicios de pago de la empresa sin permiso.<br>**Modificación:** Se pueden alterar los datos utilizados para confirmar o procesar los pagos.<br>**Indisponibilidad:** La tienda no puede comunicarse con el servicio de pagos y no puede completar las compras.               | 1. Una persona obtiene la clave utilizada para comunicarse con la plataforma de pagos.<br>2. La tienda recibe una confirmación falsa de que un pago fue realizado.<br>3. Una falla en la comunicación impide confirmar los pagos correctamente.      | 1. Guardar las claves de pago en un lugar seguro y limitar su acceso.<br>2. Comprobar directamente con la plataforma de pagos que una transacción fue realizada.<br>3. Registrar los errores de comunicación y establecer mecanismos para volver a intentar una operación de forma segura. |
